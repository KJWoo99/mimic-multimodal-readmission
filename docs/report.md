# MIMIC 멀티모달 30일 재입원 예측: 결과 보고서

설계 원칙, 성능 기대치, Phase 별 결과와 해석, 라벨 정의, 재현 방법과 코드 구조를 담음. 요약은
[README](../README.md), 저선량 부가 분석은 [lowdose](lowdose.md), 결함과 고친 경위는 [트러블슈팅](TROUBLESHOOTING.md), 모델의 쓰임과 한계는
[MODEL_CARD](MODEL_CARD.md), 보고 지침 대응은 [TRIPOD_REPORT](TRIPOD_REPORT.md) 에 있음.

## 설계 원칙

1. 예측 시점은 퇴원임. 재원일수, 재원 중 진단, 투약은 퇴원 시점에 알 수 있어 쓰지만 입원 시점 예측에는
   쓸 수 없음(그 시점엔 재원일수가 정해지지 않음). 이 금지 사용례는 Model Card 에 적음.
2. 누수는 예외로 막음. 분할 직후 개체 겹침을 검사해 위반하면 `LeakageError` 를 던지고, 행 단위 무작위
   분할을 반드시 잡는지 회귀 테스트로 고정함. 모델 입력에서 자동으로 빼는 컬럼은 아래와 같음.

| 컬럼 | 이유 |
|---|---|
| `is_last_admission` | 1이면 라벨이 항상 0 (다음 입원 기록이 없어 음성이 된 것) |
| `discharge_location` | '사망', '호스피스' 값이 결과를 그대로 알려줌 |
| `days_to_next_admission` | 결과 시점 자체 |
| `admit_year_shifted` | MIMIC-IV 는 환자별로 날짜를 시프트. 절대값에 의미 없음 |

3. PR-AUC 는 양성률과 함께 적음. 양성률 0.19 에서 PR-AUC 0.20 은 무작위와 같음. ECE 는 직접 구현해
   `calibration_curve` 기반 계산과 `1e-12` 안에서 같음을 테스트로 고정했고, 모두에게 양성률을 내는 모델도
   ECE 가 0 에 가까우므로 판별력 지표와 함께 적음.
4. 실험과 코드 상태를 묶음. git 저장소 안에서 돌리면 실험마다 커밋 해시와 dirty 여부를 남기고, 커밋되지
   않은 변경이 있으면 "재현 불가"를 경고함. 이 저장소의 결과는 git 저장소를 만들기 전에 돌려 커밋이
   `unknown` 으로 남음. 커밋을 읽지 못하면 네 항목을 모두 `unknown` 으로 적고 경고함
   (`tests/test_tracking_git_state.py`).

### 코호트 기준에 따른 재입원률 (MIMIC-IV v3.1 실측)

재원 1일 이상 + 원내 사망 제외 -> 415,231건 / 재입원률 20.73%
(선행연구 참고치 415,231건, 약 18%. 입원 수는 같음. 재입원률이 높은 것은 다음 입원을
필터 뒤 코호트가 아니라 전체 입원에서 찾기 때문임. 코호트 안에서만 찾던 이전 코드는
18.01% 로 참고치와 같음. 트러블슈팅 24번)

| 기준 | 재입원률 |
|---|---|
| 절단 포함, 예정 미제외 (= 문헌 방식) | 20.73% |
| 절단 포함, 예정 제외 (주 분석) | 19.15% |
| 절단 제외, 예정 미제외 | 33.92% |
| 절단 제외, 예정 제외 | 31.33% |

절단 포함 재입원률은 관찰 절단된 입원(전체의 38.9%)을 전부 "재입원 안 함"으로 처리한 값임.
마지막 입원은 다음 기록이 없을 뿐 재입원하지 않았다고 확인된 것이 아님.
결과를 실제로 관찰할 수 있는 입원만 보면 34% 임.

어느 한 쪽이 정답이 아니므로 양쪽을 민감도 분석으로 함께 보고함

관찰 입원을 재입원으로 세는 점 등 CMS 정의와 다른 점, 그리고 라벨을 CMS식으로 바꾼 민감도 분석은
[라벨 정의 절](#라벨-정의-cms-재입원-정의와-다른-점)에 있음.

## 라벨 정의. CMS 재입원 정의와 다른 점

라벨은 CMS 의 30일 재입원 정의를 바탕으로 만들었지만 같지는 않음. 기준은 CMS 병원 전체
재입원 측정의 방법론 보고서(Horwitz 등, Yale CORE, 2011)임. 재입원은 "퇴원 30일 안에
급성기 병원에 다시 inpatient 로 입원한 것"이고, 재입원이 다시 index 가 될 수 있음. 아래 건수는 주 분석 코호트를
다시 만들어 센 값임(`scripts/run_label_sensitivity.py` 가 `outputs/label_sensitivity_cms.json` 의 `definition_diff` 에 남김).

| 항목 | CMS 병원 전체 재입원 측정(HWR) | 이 저장소 | 크기(주 분석 코호트 415,231건) |
|---|---|---|---|
| 재입원으로 세는 입원 | 급성기 병원의 inpatient 입원 | `admissions` 의 모든 입원(관찰 입원 포함) | 양성 79,509건 중 다음 입원이 관찰 입원 32,357건(40.7%) |
| index 에서 빼는 입원 | 원내 사망, 다른 급성기 병원 전원, 자의 퇴원, 재활 입원 | 원내 사망(사망 시각 또는 `hospital_expire_flag`)만 | 전원 2,144건(0.52%), 자의 퇴원 2,588건(0.62%)이 남아 있음 |
| 대상 | 65세 이상 Medicare | 18세 이상 전체 | 없음 |
| 계획 재입원 | Planned Readmission Algorithm(시술, 진단 코드) | `admission_type` 두 값으로 근사 | 재입원률 20.73% 대 19.15% |
| 재입원을 보는 범위 | 모든 병원 | BIDMC 한 병원 | 다른 병원으로의 재입원은 보이지 않아 양성이 적게 잡힘 |

관찰 입원을 재입원으로 세는 것이 가장 큰 차이임. MIMIC-IV 의 `admissions` 는 관찰 입원을
입원 유형 중 하나로 담고 있어 여기서는 입원으로 다룸. 그래서 라벨을 CMS 식으로 바꾼 민감도 분석을 따로 함(아래 표). 퇴원처가 `DIED` 인데
`hospital_expire_flag` 가 0 이고 사망 시각도 없는 203건은 코호트에 남아 있음. 그중 13건은
30일 안에 다시 입원해 실제로 사망한 것이 아니므로, 기록 불일치로 보고 원내 사망 판정은
사망 시각(`deathtime`)과 `hospital_expire_flag` 로만 함(`src/cohort.py`). 두 개수는
`outputs/label_sensitivity_cms.json` 의 `definition_diff` 에 있음.

### CMS식 라벨 민감도

주 라벨은 그대로 두고, CMS 정의에 가깝게 바꾼 라벨로 같은 파이프라인을 다시 돌림(`scripts/run_label_sensitivity.py`,
결과 `outputs/label_sensitivity_cms.json`. 주 라벨로 다시 낸 Phase 1 AUROC 와 융합 lift 가 주 결과와 다르면 멈춤). 관찰 입원(`EU OBSERVATION`,
`OBSERVATION ADMIT`, `DIRECT OBSERVATION`, `AMBULATORY OBSERVATION`)을 index 와 재입원 양쪽에서 빼고, 다른 급성기 병원
전원과 자의 퇴원을 index 에서 빼고, 퇴원 당일의 다음 입원은 전원으로 보고 재입원으로 세지 않음. 분할(환자 단위
seed 42), 피처, 모델, 예정 재입원 규칙은 주 분석과 같음. 영상 기여는 Phase 3 의 세 융합 방식을 같은 환자 배정으로
다시 측정함(인코더가 본 환자가 test 로 넘어가지 않게 분할을 다시 뽑지 않음).

| 라벨 | index 입원 | 재입원율 | Phase 1 test AUROC | 영상 기여(Fusion 최고 − EHR, CNN / RAD-DINO) |
|---|---:|---:|---:|---|
| 주 분석(이 저장소) | 415,231 | 19.15% | 0.7075 | −0.0153 / +0.0014 |
| 관찰 입원을 index 와 재입원에서 뺌 | 282,818 | 13.91% | 0.7190 | 재지 않음 |
| CMS식(위 + 전원, 자의 퇴원 index 제외, 당일 재입원 제외) | 279,388 | 13.26% | 0.7237 | −0.0077 / +0.0023 |

- 빠진 것: 관찰 입원 index 132,413건, 전원과 자의 퇴원 3,430건. 당일 재입원 1,468건은 재입원에서 빠짐
- 재입원율은 19.15% 에서 13.26% 로 내려가고 AUROC 는 조금 오름
- 재현: 처음에는 이 분석을 저장소 밖 대조 스크립트로 쟀는데, 결과와 코드가 저장소에 없어 재현 경로가 없었음. 같은
  계산을 저장소로 옮겨 다시 돌렸고 모든 값이 같음

해석: 두 결론은 그대로임. Phase 1 AUROC 는 여전히 문헌 범위(0.65\~0.75) 안이고, 영상은 어느 라벨에서도 판정선(+0.02)에
못 미쳐 "영상이 보태지 않는다" 임. 라벨마다 대상 집단과 양성률이 달라 AUROC 를 같은 자로 견줄 수는 없음.

## Phase 1 결과. EHR 단독 베이스라인

`outputs/phase1_metrics.json` 에 그대로 저장돼 있음. 투약 테이블(`prescriptions.csv.gz`,
1,700만 행) 포함 실데이터 전체로 재실행한 결과임. 초기 실행은 이 테이블 없이
33개 피처로만 돌았음.

```
코호트   415,231 입원 / 181,595 환자 (입원당 2.29건)
분할     환자 단위 train 290,781 / val 41,287 / test 83,163
피처     42개(투약 9개 포함)   모델 XGBoost (scale_pos_weight 4.22)
```

| 지표 | 값 | 기준 |
|---|---:|---|
| AUROC | 0.7075 | 문헌 ML 0.65\~0.75 |
| PR-AUC | 0.3832 | 무작위 0.1929 |
| Brier | 0.2155 | 상수 예측 0.156 |
| ECE | 0.2669 | 0 에 가까울수록 좋음 |
| EER | 0.3491 | 놓침과 오경보가 같아지는 지점의 오류율 |

> Phase 4, 5 는 투약, 시술 피처를 빼고 32개로 다시 적합함. 그래서 이 문서의
> 보정, 서브그룹, SHAP, 결정곡선 값은 이 표가 아니라 그 모델 기준이고, AUROC 가
> 0.7011 로 0.0064 낮음. 두 수치가 같은 모델의 것인 줄 알고 섞어 읽으면 안 됨.

AUROC 는 문헌 범위 안이고 누수를 의심할 선(0.85)과 멂. EER 은 놓침과 오경보가 같아지는 점의 오류율로, 운영점은
아님(운영점은 Phase 5 에서 알림 용량으로 정함).

투약 테이블 없이(투약 피처 9개가 빠짐) 같은 분할로 다시 재면 AUROC 가 0.7075 에서 0.7040 으로,
0.0036 만큼 떨어짐(`outputs/phase1_metrics_no_rx.json`, `run_phase1.py --no-prescriptions`). 1,700만 행을 읽어 얻은 이득은 이 정도임. 성능은 Charlson, 재원기간, 이전입원횟수
같은 소수의 임상 피처에서 나옴.

확률값은 그대로 쓸 수 없음. `scale_pos_weight` 때문에 확률이 위로 밀려 Brier 0.2155 가 모두에게 양성률(0.1929)을
내는 상수 모델(0.156)보다 나쁨. 보정은 Phase 4 에서 함.

## Phase 1.5 결과. 결측 모달리티 진단 (CXR 유무는 MNAR)

`outputs/phase1_5_metrics.json`. 570GB 영상을 받기 전에, 메타데이터(58MB)만으로
CXR 보유 여부가 무작위 결측(MCAR)인지 확인함.

| | |
|---|---|
| CXR 보유 입원 | 8.6% (35,601 / 415,231) |
| 보유군 재입원률 | 24.93% |
| 미보유군 재입원률 | 18.61% |
| 위험비(RR), 보정 없음 | 1.340 [95% CI 1.314–1.366] |
| 위험비(RR), 재원일수 4분위 보정(Mantel-Haenszel) | 1.202 [환자 단위 95% 구간 1.174–1.228] |

신뢰구간은 입원 415,231건을 서로 독립으로 보고 계산함. 실제로는 한 환자가 평균 2.29건 들어 있어 같은 환자의
입원끼리 결과가 닮음. 그래서 환자 단위로도 다시 측정함.

- 조 RR: 환자 181,595명을 단위로 다시 뽑는 부트스트랩(1,000회)으로 재 보니 [1.308, 1.368] 로 거의 같음
  (`phase1_5_metrics.json` 의 `mnar.rr_patient_bootstrap`)
- 보정 RR: 재원일수가 교란변수라 주 수치는 보정 RR(1.202, `mnar.los_adjusted`, 트러블슈팅 2)로 보고함. 같은 환자 단위
  부트스트랩으로 재면 [1.174, 1.228] 임(`mnar.los_adjusted.patient_bootstrap`)
- 아래 판정은 둘 다에서 같음
JSON 의 `mnar.verdict` 문장은 진단 단계에서 조 RR 로 쓴 것이고, 보정 RR 로 쓴 문장은 `mnar.verdict_adjusted` 임.

판정: MNAR 강함. 영상을 찍은 입원이 재입원 위험도 실제로 더 높음. "영상이
없다"는 사실 자체가 무작위가 아니라 임상적으로 의미 있는 신호임. Phase 3 의
결측 모달리티 처리(드롭아웃, fallback)가 이 결과 위에서 설계됨.

## Phase 2 결과. CXR 영상 단독 모델

> 처음에는 학습이 되지 않은 DenseNet121 로 "영상은 자세만 본다"고 적음(트러블슈팅 11). 아래는 네 인코더를 같은
> 설정(384px / batch 64 / 40에폭 / patience 8 / aug strong / cosine)으로 다시 돌린 값임.

| 인코더 | 영상 AUROC | 자세 대비 | 판정 | best epoch |
|---|---:|---:|---|---:|
| DenseNet121 (기록 모델) | 0.5442 | +0.0339 | 판단 보류 | 10 / 18 |
| ResNet50 | 0.5585 | +0.0482 | 판단 보류 | 13 / 21 |
| EfficientNet-B0 | 0.5637 | +0.0534 | 영상을 봤다 | 7 / 15 |
| RAD-DINO (동결, 518px) | 0.5853 | +0.0749 | 영상을 봤다 | 없음 |

DenseNet121 이 가장 낮은 순서는 학습 실패를 고치기 전과 같음. 지금은 10에폭까지 나아지다 조기종료로 끝나는 정상
학습을 하고도 가장 낮으므로, 백본에 따라 판정이 갈리는 것은 학습 실패의 부산물이 아님.

- 판정선(사전에 정함): 자세 기준선 대비 ≥0.05 면 "영상을 봤다", <0.02 면 "자세만 본 것", 그 사이는 보류
- 네 값이 0.034\~0.075 에 흩어져 있음
- EfficientNet-B0 의 "영상을 봤다"는 시드 42 한 번의 값임. 같은 설정을 시드만 바꾼 확인 실행 3시드의 평균은 +0.0477 로
  "판단 보류"임(Phase 6 확인 실행)
- 판정선 +0.05 를 한 번의 운이 아니라 여러 번 넘은 것은 RAD-DINO 하나임(뒷단 세 가지 모두 AUROC 0.572\~0.585, Phase 2-C)

해석: 백본 하나로는 판정을 정할 수 없음.

## Phase 3 결과. Fusion, 결측 모달리티(M1a), V1, V3

`outputs/phase3_metrics.json`(CNN), `outputs/phase3_metrics_raddino.json`(RAD-DINO).

### V1. 분할 방식이 만드는 부풀림

### Fusion. 세 방식 모두, 두 인코더 모두 보태지 않음

영상 보유 부분집합(test 7,168) 기준. EHR 단독 0.6597.

| 융합 방식 | 파인튜닝 CNN | 동결 RAD-DINO |
|---|---:|---:|

차원 수가 EHR 을 압도해서 생긴 문제가 아님. 영상 팔이 train 에서만 잘 맞는

줄이고, 자기 학습 데이터를 맞힌 값이 되지 않도록 환자 단위 5겹 out-of-fold 예측을 씀.

> 그래서 영상이 쓸모없다고 결론 내리지는 않음. 영상 단독으로는 자세 기준선을 넘고, 촬영 메타데이터는
> 동결 RAD-DINO 만 판정선 이상으로 넘음(파인튜닝 CNN 은 +0.0120 으로 못 넘음, V3, Phase 2-C). 그런데 EHR 에 더하면 늘지 않음. 가장 그럴듯한 해석은 영상이 담은
> 정보를 EHR 이 이미 담고 있다는 것임. 재입원 위험의 대리지표(중증도, 과거 입원력,
> 동반질환)가 양쪽에 다 들어 있는 것으로 보임. 융합 방식이 신호를 못 살렸을 가능성은
> 세 방식을 모두 재서 줄였지만 없앨 수는 없음.

### M1a. 결측 처리는 성능을 지키고, 픽셀 입력은 성능을 낮춤

| 부분집합 | n | EHR | EHR+영상유무 | Fusion+M1a | 픽셀 몫 |
|---|---:|---:|---:|---:|---:|
| 전체 코호트 | 83,526 | 0.6989 | 0.7005 | 0.6969 | −0.0036 |
| 영상 있음 | 7,168 | 0.6532 | 0.6694 | 0.6447 | −0.0247 |

영상 유무만으로도 오르므로(EHR 0.6989 -> EHR+영상유무 0.7005, Phase 1.5 의 MNAR), 픽셀의 몫은 유무 정보를 양쪽에 똑같이

- 결측 처리 판정. 영상 없는 입원에서 성능이 떨어지지 않음(−0.0008). 드롭아웃 학습

## Phase 6 결과. 절제실험. 설정을 바꿔가며 무엇이 병목인지 찾음

트러블슈팅 13에서 "이 프로젝트의 병목은 과적합이다"라고 적음. 그러면 과적합을 줄이는 축들

기준이고, test 는 불러오지도 않음(`scripts/run_ablation.py`).

백본은 EfficientNet-B0 임. 절제를 설계한 시점(트러블슈팅 11, 13)에 12에폭 한도 안에서 유일하게 학습 신호를 보인 백본이었고,
질문이 학습 조건이라 백본은 고정함. 기준선의 학습 조건(384px, batch 64, aug strong, 40에폭, patience 8, cosine,
weight decay 1e-4, freeze 3)은 기록 모델을 학습한 조건과 같음(`outputs/phase2_metrics.json`).

| # | 바꾼 것 | val PR-AUC | 기준선 대비 | best/실행 |
|---|---|---:|---:|---:|
| 1 | 기준선 | 0.3297 | 없음 | 7/15 |
| 2 | size 384 -> 224 | 0.3169 | −0.0129 | 7/15 |
| 3 | aug strong -> medium | 0.3145 | −0.0152 | 7/15 |
| 4 | lr_backbone 1e-4 -> 3e-4 | 0.3125 | −0.0172 | 11/19 |

여덟 번 다 조기종료로 끝남. 에폭 한도에 걸려 끊긴 것은 없음. 설정을 바꾼 일곱 회차가
모두 기준선 아래임. 그래도 순위를 읽기 전에 같은 설정을 시드만 바꿔 두 번 더 돌림.

### 시드만 바꿨을 때의 흔들림

| 설정 | seed 42 | seed 43 | seed 44 | 평균 | 표준편차 |
|---|---:|---:|---:|---:|---:|
| #1 기준선 | 0.3297 | 0.3127 | 0.3145 | 0.3190 | 0.0093 |

- 판정선을 이 표준편차의 2배(0.0187)로 두면 #6(aug light, −0.0271)만 "악화"이고 나머지 여섯은 "차이 없음"임. 이 판정은
  같은 시드(42)의 기준선 한 번 값과 견준 것임
- 기준선 세 시드 평균(0.3190)과 견주면 #6 도 −0.0163 으로 판정선 안이고, #6 은 시드를 한 번만 돌림
- 기준선보다 나은 설정은 어느 쪽으로 견줘도 없음. 가장 가까운 #7(weight decay 1e-3)도 −0.0001 임
- 의무 5회 뒤 #6\~#8 이 연속 미개선 3회라 규칙대로 8회에서 멈춤

### 주장하는 것

해상도, 증강, 학습률, 동결 구간, weight decay 를 바꿔도 시드 잡음 안에서 기준선을 넘지 못함. 증강을 light 로 줄이면
나빠지는 쪽으로 보이지만 같은 시드끼리 견줄 때만 판정선 밖이라 방향으로만 적음. "영상이 EHR 위에 얹는 정보가 거의 없다" 는
앞 Phase 의 결론도 달라지지 않음.

### 주장할 수 있는 범위

판정선 0.0187 은 기준선을 시드만 바꿔 세 번 돌린 표준편차(0.0093)의 2배임. 표본이 셋뿐이라
표준편차 자체가 불안정하므로 2배를 써서 보수적으로 정함.

이 값이 재는 것은 초기화, 배치순서에서 오는 변동뿐임. 분할 시드는 42 로
고정함. 분할까지 바꾸면 앞 실행의 val 환자가 뒤 실행의 test 로 들어가기 때문임.
실제 변동폭은 이보다 크면 컸지 작지 않음.

- 증강 강도는 light 0.3027 -> medium 0.3145 -> strong 0.3297 -> extreme 0.3176 으로 오르다 마지막에 꺾임
- 이웃 단계의 차이(0.0118, 0.0152, 0.0121)가 모두 기준선을 시드만 바꾼 폭(0.0170) 안임
- light 가 나쁘다는 것도 같은 시드 기준선과 견줄 때만 판정선 밖임

해석: 이 모양도 우연일 수 있음. "strong 이 최적이다"도 "증강을 늘리는 방향이 맞다"도 주장하지 않음.

설정마다 분할 시드를 3\~5개 돌리는 것(약 12시간)은 영상 단독 AUROC 0.56 수준에서 임상적으로 달라질 것이 없어 하지 않고
한계로 적음. 회차별 가설과 판단은 [EXPERIMENT_LOG.md](EXPERIMENT_LOG.md) 에 있음.

### 확인 실행. 이긴 설정으로 test 를 한 번 봄

절제에서 기준선을 넘은 설정이 없어 승자는 기준선(#1)임. 그 설정(384px, batch 64,
aug strong, freeze 3, weight decay 1e-4, cosine)으로 초기화 시드 3개를 돌림. 분할 시드는
42 로 고정함: 분할까지 바꾸면 앞 실행의 val 환자가 뒤 실행의 test 로 들어감.

| 초기화 시드 | val PR-AUC | test AUROC | test PR-AUC | 자세 대비 | 판정 |
|---|---:|---:|---:|---:|---|
| 42 | 0.3297 | 0.5637 | 0.2999 | +0.0534 | 영상을 봤다 |
| 43 | 0.3127 | 0.5567 | 0.2995 | +0.0464 | 판단 보류 |
| 44 | 0.3145 | 0.5538 | 0.2945 | +0.0434 | 판단 보류 |
| 평균 | 0.3190 +/- 0.0093 | 0.5581 +/- 0.0051 | 0.2979 +/- 0.0030 | +0.0477 +/- 0.0051 | |

시드 42 는 절제 기준선, Phase 2 의 EfficientNet-B0 와 설정, 시드가 같고 val(0.3297)과 test
AUROC(0.5637)가 이번 결과에서는 소수 넷째 자리까지 같음. CUDA 커널이 비결정적이라 두 러너가 늘 같은 값을
낸다고 주장하지는 않음(트러블슈팅 16).

- 세 시드 모두 "자세를 본 것" 선(+0.02)은 넘음. 영상이 자세 정보만 읽은 것은 아님
- "영상을 봤다" 선(+0.05)을 넘은 것은 시드 42 하나, 세 시드 평균 +0.0477
- 같은 부분집합의 EHR 은 0.6613 이라, 영상 단독으로는 자세를 넘지만 EHR 에는 못 미침
- 초기화만 바꿨을 때 val 이 +/- 0.0093, test AUROC 가 +/- 0.0051 흔들림. 분할까지 바꾼 폭은 재지 않음(보통 더 큼)

해석: Phase 2 에서 EfficientNet-B0 가 받은 "영상을 봤다" 판정은 초기화 시드 하나에 기댄 것이고, 세 시드로 보면 "판단 보류"임.
판정선은 사전에 정한 값 그대로 두고 이 흔들림을 결과와 함께 적음. 절제에서 설정을 바꾼 일곱 회차가 기준선과 벌어진
폭(0.0001\~0.0271) 대부분이 이 폭의 두 배 안이라, 앞 절의 결론("기준선을 넘은 설정이 없다, 최적값은 주장하지 않는다")은
바뀌지 않고 근거가 하나 더 붙음.

## 부가 분석. 저선량 모사와 복원이 소견 분류에 주는 영향

재입원과는 별개인 부가 분석이라 [docs/lowdose.md](lowdose.md) 로 따로 둠. 요약하면 518px RAD-DINO 동결 특징과 선형
프로브로 보는 소견 분류는 선량비 1/32 까지 AUROC 가 떨어지지 않았고(1/4 하락 0.0000 [-0.0002, 0.0003]), 그래서
사전등록의 주 지표인 복원 회복률은 계산하지 않음.

## 재현 방법

명령은 [README 실행 절](../README.md#실행)에 있음. 아래는 인자를 그렇게 고른 이유임.

영상 학습은 기본값이 아니라 절제실험으로 고른 설정으로 돌림. 인자를 생략하면
12에폭, batch 32, 224px, 증강 medium, 스케줄러 없음으로 돌아 아래 표의 숫자가 나오지
않음. `--workers` 는 데이터 로더 수인데, 값이 바뀌면 증강 난수 순서가 달라져
같은 시드라도 궤적이 조금 달라짐. 아래 수치는 전부 16으로 낸 것임.

절제실험은 한 번에 하나씩 바꿔 8회, 기준선을 시드만 바꿔 2회 더 돎. 각 회차의 인자와
가설은 `docs/EXPERIMENT_LOG.md` 에 그대로 실려 있음.

확인 실행은 절제 승자의 설정을 test 에서 한 번 봄. 시드를 셋 돌려 변동폭을 함께 냄.
지금 승자는 기준선(#1)이라 기준선 설정으로 돎.

나머지는 임베딩 캐시를 읽으므로 CPU 로 돎.

## 모델 가중치 저장과 지문 (재현성)

Phase 2 는 원래 학습한 가중치를 메모리에만 두고 버림. 두 가지가 문제였음.

- 재사용 불가. Phase 3(Fusion), 4(Grad-CAM), 5(윈도우 실험)가 전부 같은 인코더를
  쓰는데 매번 50분씩 재학습해야 함.
- 증거 부재. 당시 보고한 AUROC(0.5422)가 어떤 가중치에서 나왔는지 특정할 수 없었음.

`src/checkpoint.py` 를 추가해 둘 다 해결함.

```
outputs/models/phase2_cxr_densenet121.pth    가중치 (27MB, .gitignore 로 차단)
outputs/models/phase2_cxr_densenet121.json   메타 사이드카 (차단)
outputs/phase2_metrics.json -> checkpoint.sha256   <- 지문만 저장소에 올라간다
```

지문은 파일이 아니라 텐서 값에서 뽑음(`torch.save` 는 zip 이라 같은 가중치도 파일 해시가 달라짐). 불러올 때 지문을
재검증해 다른 실행의 가중치를 잘못 집어드는 것을 막음.

가중치 파일 자체는 MIMIC 파생물이라 저장소에 올리지 않음(README 데이터). 해시는 데이터가
아닌 16진수 문자열이라 공개해도 안전함.

Phase 2 도 MLflow(실험명 `phase2-cxr`)에 하이퍼파라미터와 에폭별 손실을 남김. git 커밋은 이 저장소의 결과에서
`unknown` 임(이 문서 설계 원칙 4번).

## Phase 2-B. 임베딩 캐시

`scripts/run_phase2_embed.py` 는 학습된 인코더로 영상 35,599장을 한 번만 통과시켜
1024차원 특징 벡터를 저장함. 이후 Fusion(Phase 3), 분할 방식 비교(V1), 누수 A/B(V6),
시간분할(V7), 촬영시점 윈도우 실험(M2) 은 원본 이미지 대신 이 캐시를 읽으므로
GPU 없이 CPU 로 돌아감. 인코더가 고정되므로 "비교 조건이 동일하다" 도 자동
보장됨.

Grad-CAM(V5) 만은 예외임. 원본 픽셀에 역전파를 걸어야 해서 체크포인트를 직접 불러
GPU 에서 돌림.
