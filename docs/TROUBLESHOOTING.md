# 트러블슈팅. 실측으로 잡은 결함

결함은 대부분 회귀 테스트로 고정함.

## 1. 점이연 상관만 보면 오판함

- 증상: 결측 모달리티 진단(M1-b)에 점이연 상관을 쓰자 `r = 0.045`, "효과크기 작음" 이 나옴. 그런데 재입원률은
  24.93% 대 18.61% 로 1.34배였음
- 원인: 두 집단 크기가 8.6% 대 91.4% 로 극단적으로 불균형하면 점이연 상관이 구조적으로 작아짐. `r` 만 보면
  "연관 없음 -> MCAR" 로 결론 내게 됨
- 수정: 위험비를 함께 계산함
- 결과: 판정이 "MNAR 강함" 으로 뒤집힘

## 2. 그 위험비가 재원일수로 교란돼 있었음

- 원인: `has_cxr` 은 재원일수와 가장 강하게 연관된 관측 변수라(r=0.127, 재원 4분위 Q1 3.7% -> Q4 16.1%) 재원일수가
  교란변수임
- 결과: 조 RR 1.340(1.314 \~ 1.366)이 Mantel-Haenszel 보정 뒤 1.202(1.174 \~ 1.228, 환자 단위 부트스트랩)로 줄었음. 층별 RR 이
  네 층 모두 1 을 넘어 연관은 유지됨
- 비고: 주 수치는 보정 RR 로 보고함(`phase1_5_metrics.json` 의 `mnar.los_adjusted`)

## 3. 입력에 섞여 있던 문제 컬럼 3건

전처리에서 잘못 들어온 컬럼이라 입력에서 뺌. 설계 원칙의 제외 목록이나 V6 누수 A/B 와는 다른 묶음임.

1. `is_last_admission`: 1이면 라벨이 늘 0
2. `anchor_age_pat`: `cohort.py` 와 `features.py` 가 `patients` 를 각각 merge 해 생긴 중복
3. `n_procedures`: 원천 테이블이 없을 때 전부 결측

## 4. `admit_year` 는 쓸 수 없음. MIMIC-IV 날짜 시프트

- 원인: MIMIC-IV 는 환자별로 날짜를 무작위로 옮겨 연도 절대값에 뜻이 없고, 실제 기간은 `anchor_year_group` 에만 있음
- 수정: 피처에서 빼는 것에 그치지 않고 시간 분할 검증(V7)도 `anchor_year_group` 으로 함. 옮겨진 연도로 나누면 사실상
  무작위 분할이 됨

## 5. 우측 절단. 마지막 입원 38.9% 가 무조건 음성이 됨

- 증상: 각 환자의 마지막 입원은 다음 기록이 없어 자동으로 음성이 되지만, "재입원하지 않았다" 와 "관찰이 끝났다" 는 다른
  사건임
- 결과: 절단 포함 재입원률은 20.73%(문헌 방식), 결과를 관찰할 수 있는 입원만 보면 33.92%(예정 재입원 제외 시 19.15%,
  31.33%)
- 수정: 날짜 시프트로 전역 관찰 종료일을 알 수 없어, 어느 한쪽을 정답으로 두지 않고 민감도 분석으로 함께 보고함

## 6. 데이터 품질. `dischtime <= admittime` 오류 180건

- 증상: 퇴원 시각이 입원 시각보다 이르거나 같은 레코드가 180건 있음. `min_los_days=0` 이면 재원 필터를 통과함
- 수정: 필터와 무관하게 먼저 제거하고 참여자 흐름에 기록함

## 7. 다운로드가 고른 파일과 학습이 고른 파일이 달랐음. 코호트 18.6% 소실

- 증상: 내려받은 35,599장 중 6,096장(17.1%)은 정면이 있는데도 측면이었고, 학습 인덱스는 그 정면 파일이 없어 6,620건을
  탈락시켜 28,981건만 남김
- 원인: 한 study 의 대표 영상 1장을 고르는 규칙이 다운로드(알파벳순 첫 파일)와 학습 인덱스(정면 우선)에서 달랐음. 정면 우선
  옵션은 필요한 컬럼이 만들어지지 않아 한 번도 실행되지 않음
- 수정
  - `linked_studies()` 가 정면 우선으로 대표를 정함
  - `build_cxr_index()` 는 디스크에 있는 파일 중에서 고름
- 결과: 6,618건을 되살림(정면이 없어 측면을 쓴 건수는 `flags` 로 따로 보고)

### 당시 다시 돌린 결과

학습 실패를 고치기 전(11번) 당시 이 수정으로 다시 돌린 값임.

- 코호트: 28,981 -> 35,599
- 되살아난 영상이 대부분 측면이라 AP 비율 76.1% -> 63.0%
- 영상 AUROC 0.5422 -> 0.5012, 자세 대비 +0.0326 -> −0.0141 로 떨어져 판정이 "자세를 본 것" 으로 바뀜
- 측면을 정면으로 바꿔도(8번) 그대로였고, 이 판정은 11번에서 학습 실패를 고치며 다시 바뀜

## 8. 측면 오염을 걷어내고 다시 학습함. 당시 판정은 그대로였음

이 항목의 판정과 수치는 학습 실패를 고치기 전(11번) 당시 이야기임. 11번에서 고친 뒤 판정은 "판단 보류"(자세 대비
+0.0339)가 됨.

- 수정: 7번에서 미룬 정면 6,098장을 받아 다시 학습함. 정면 비율 77.5% -> 93.3%(코호트와 분할은 그대로)
- 결과(당시): 영상 AUROC 0.5012 -> 0.5037, 자세 대비 −0.0141 -> −0.0067 로 판정("자세를 본 것")이 그대로였음. ECE 는
  0.2070 -> 0.2985 로 나빠짐
- 결과: 측면 오염 탓이라는 설명은 실측으로 배제됨

## 9. Phase 3 코드에서 잡은 결함 4건

새로 쓴 코드에도 같은 점검을 걸어 네 건을 찾음(당시 값).

1. 분할 방식 비교(V1)에서 PCA 를 환자 단위 train 으로 한 번만 적합해 무작위 팔에 씀. 팔마다 따로 적합하자 부풀림이
   +0.0039 -> +0.0175 로 커짐
2. M1a 판정을 하나로 묶어, 결측 처리가 버티는지(영상 없는 입원)와 픽셀이 보태는지(영상 있는 입원)가 섞임. 둘로 가름
3. Fusion 에만 "영상 있음" 지표가 들어가 픽셀의 몫과 영상 유무의 몫이 섞임. EHR + 영상유무 기준선을 더해 떼어냄
4. 재학습 뒤 README 가 옛 수치를 들고 있었음. 문서가 인용한 수치를 산출물과 대조하는 테스트를 넣고, 일부러 옛 값으로
   되돌려 실패하는지 확인함(`tests/test_output_claims.py`)

## 10. Phase 4, 5 에서 잡은 결함 4건. 둘은 결론의 의미를 바꿈

결론의 의미를 바꾼 둘:

1. 시간 분할(V7) 대조군을 전체 무작위 분할 모델로 미래 구간에 평가해, 대조군이 자기 학습 데이터를 채점하고 있었음. 같은
   표본 풀에서 환자 단위 분할을 다시 만들어(시드 3개 평균) 재측정함. 판정("시간 이동에 견딘다")은 그대로지만 고치기 전
   숫자는 비교 자체가 성립하지 않는 값이었음(지금 값은 report V7 절)
2. 서브그룹 보정(V4)을 원본 확률로만 재 집단 간 격차가 묻힘. 교정된 확률로 한 번 더 재자 전체 ECE 는 낮은데 보험 축의
   격차가 남음(지금 값은 report V4 절)

나머지 둘은 실행 오류였음:

3. pandas 3.0 에서 `astype(str)` 이 결측을 그대로 두어 정렬에서 멈춤. 저장소 전체를 점검해 세 곳을 고침
4. `reliability_curve` 가 dict 를 주는데 튜플로 풀어 쓰는 코드를 실행 전에 찾아 고침

## 11. 학습이 실패한 인코더의 점수를 "신호 없음"으로 읽음

- 증상: "CXR 영상은 자세만 본다" 는 첫 결론은 인코더가 학습되지 않아서 나온 것이었음. 기록 모델 DenseNet121 은 train
  loss 가 6에폭 동안 0.008 밖에 안 내려갔고 best 가 1 에폭이었는데, 그 test AUROC 0.5037 을 "신호 없음" 으로 읽음
- 확인
  - 같은 조건에서 백본만 바꾸자 판정이 계단식으로 달라짐(당시 12에폭 한도 값: ResNet50 +0.0462, EfficientNet-B0 +0.0524)
  - 흉부 X선 88만 장으로 자가지도 학습된 RAD-DINO 를 동결해 선형 프로브만 얹어도 0.5852 가 나와 신호가 표현 안에 있음
- 함께 고친 것
  - LR 스케줄러 없음: 단계별 cosine 을 넣음
  - 해로운 좌우반전 증강(우심증처럼 보임): 뺌
  - 224px 해상도: 384px 로
- 지금: report Phase 2 인코더 비교 표(DenseNet 0.5442, ResNet50 0.5585, EfficientNet-B0 0.5637, RAD-DINO 0.5853)
- 결과: 영상 단독으로는 자세 기준선을 넘지만 EHR 에 더하면 늘지 않는다는 지금 결론은 이 수정 뒤에 나옴. 뒤집힘의 핵심
  수치는 문서 대조 테스트에 등록함

## 12. M2 는 촬영 시점이 아니라 데이터 양을 재고 있었음

- 증상: 촬영 시점 창마다 학습 표본이 7배까지 달라(24h 4,939 대 전체 35,599) 시점의 효과와 표본 크기의 효과가 섞임
- 수정: 가장 좁은 창의 학습 크기(3,480건)에 맞춰 줄인 팔을 함께 측정함. 판정은 표본을 맞춘 쪽으로 함
- 결과(당시): RAD-DINO 폭이 0.0647 -> 0.0418 로 줄었음
- 지금: 라벨을 고친 뒤(24번) 다시 잰 값에서는 폭이 맞춘 쪽에서 오히려 커짐(0.0213 -> 0.0285). 맞추지 않은 폭으로는 시점을
  말할 수 없다는 판단은 그대로임

## 13. 12에폭 한도가 조기종료 역할을 하고 있었음. 에폭을 늘리자 과적합이 늘었음

- 증상: 11번 뒤 스케줄러를 붙여 40에폭으로 다시 돌리자(당시 실행) train loss 는 0.9656 -> 0.5034 로 더 내려갔는데 val 은
  오르지 않음
- 원인: 12에폭 한도가 우연히 조기종료 역할을 하고 있었고, 이 프로젝트의 병목은 과적합임
- 함께 찾은 것: 224px 와 384px 는 val 과 test 가 다른 답을 줌(val 은 224, test 는 384 가 높음). 설정을 여러 번 바꾸며
  test 를 보면 그 운이 test 에 섞임
- 수정: 절제 러너는 test 를 불러오지 않음
- 지금: Phase 2 는 40에폭 한도, cosine, 조기종료로 돌고 한도에 닿는 실행이 없음

## 14. 설정을 바꿔가며 추적한 기록이 없었음

- 증상: MLflow 런은 있었지만 모델 이름만 다르고 설정은 같아, 설정을 바꿔 추적한 기록이 없었음
- 결과: 그 공백 때문에 DenseNet 의 학습 실패를 알아채지 못함(11번)
- 수정
  - 증강 강도를 단계로 노출함(`src/cxr_dataset.py`, `medium` 이 옛 설정과 같음)
  - 한 축씩 바꾸며 가설과 결과를 남기는 `scripts/run_ablation.py` 와 일지를 만드는 `scripts/render_experiment_log.py` 를 더함

## 15. AUROC 변동폭으로 PR-AUC 차이를 판정하려 함

- 증상: 절제 한계를 "aug=strong 의 우위 +0.0064 는 분할 변동폭 0.012 보다 작다" 로 쓰려 함
- 원인: 0.012 는 Fusion 절의 AUROC 차이(0.5844 대 0.5725)이고 절제 표는 PR-AUC 였음. 두 지표는 바닥이 달라(당시 양성률
  0.166) 한쪽의 변동폭을 다른 쪽에 댈 수 없음
- 수정: PR-AUC 쪽 변동폭은 잰 적이 없으므로 우위를 부정할 근거도 긍정할 근거도 없다고 고쳐 적고, 증강 사다리의 방향만 남김
- 함께 고친 것: 숫자를 인용할 때 단위를 같이 옮기고, 이 단서를 문서에서 요구하는 검사를 `tests/test_output_claims.py` 에 둠

## 16. 시드를 고정했는데도 두 스크립트의 학습 결과가 달랐음

이 항목의 수치와 "이미 나온 결과는 다시 돌리지 않았다" 는 라벨을 고치기 전(24번) 당시 이야기임. 24번에서 절제실험까지
전부 다시 만들었고, 지금 확인 실행 값은 report 의 확인 실행 절에 있음.

- 증상: 같은 설정, 같은 시드인데 절제 러너와 확인 실행의 val 이 달랐음(0.2826 대 0.2812)
- 원인: 두 스크립트 모두 시드를 걸기 전에 모델을 만들어, 분류기 헤드가 앞에서 쓴 난수 양에 따라 다르게 초기화됨
- 수정: `train.set_seed()` 를 모델 생성 직전에 부르게 하고, 성질과 호출 순서를 `tests/test_train_schedule.py` 로 고정함
- 비고: CUDA 비결정성 때문에 완전 일치는 요구하지 않고, 확인 실행 3시드가 만든 폭에 견줌
- 결과(당시): 결과를 다시 돌리지 않고 "확인 실행이 절제를 그대로 재현한다" 는 주장만 접음

## 17. 새 설정으로 학습해 놓고 임베딩은 옛 체크포인트에서 뽑고 있었음

- 증상: Phase 2 를 새 설정(`--tag`)으로 다시 학습했는데 임베딩과 그 위의 Phase 3, 4, 5 가 2주 전 인코더의 것이었음. 오류
  없이 옛 값이 나와 갱신 시각을 대조하다 찾아냄
- 원인: Phase 2-B(임베딩)는 `phase2_metrics.json` 한 곳의 체크포인트만 읽음
- 수정
  - `--tag` 로 쓸 가중치를 정함
  - 학습 해상도와 요청 해상도가 다르면 멈춤
  - 임베딩 요약의 `source_metrics` 가 기록상의 모델인지 테스트로 봄
- 비고: 지문 대조는 옛 인코더끼리 일치해 이것을 잡지 못함

- 수정: 판정선을 기준선 시드 반복의 표준편차 두 배로 바꾸고, 후보 설정은 시드 42 로 한 번씩 돌려 견줌

## 19. 라벨을 보고 학습한 인코더의 임베딩을, 그 인코더가 본 환자에게 다시 씀

- 증상: Phase 2 는 영상 보유 입원만 따로 나눠 인코더를 학습했는데, M1a 는 전체 코호트를 다시 나눠 평가해 test 의 영상 보유
  7,213행 중 5,019행(69.6%)이 인코더의 학습 데이터였음(M2 는 창이 좁을수록 더 심함)
- 확인
  - 인코더가 본 행의 픽셀 기여는 +0.2102, 처음 보는 행은 −0.0970 이었고 EHR 난이도는 같았음
  - 라벨을 본 적 없는 RAD-DINO 에서는 격차가 사라짐
  - 임베딩을 직접 탐침하자 CNN 은 학습한 환자에서 0.9064, 처음 보는 환자에서 0.5471
- 수정: `src/splits.py` 의 `subject_folds`, `split_with_fixed_folds` 로 앞선 분할의 소속을 물려받게 해, 인코더가 학습한
  환자가 어떤 실험의 test 에도 들어가지 않음. 겹침을 막는 테스트 4개로 고정함
- 결과(당시): M1a 판정이 "픽셀이 보탠다" 에서 "오히려 깎는다" 로, M2 판정이 "촬영 시점이 결과를 바꾼다" 에서 "바꾸지 않는다"
  로 뒤집힘
- 지금: 그 뒤 인코더를 다시 학습하고 라벨을 고쳐(24번) 다시 만든 지금 값은 M1a 픽셀 기여 −0.0247, M2 폭 0.0353(표본 맞춤,
  CNN)임

## 20. 영상이 없다는 사실이 학습과 평가에서 다른 모양이었음

- 증상: M1a 는 학습 때 영상 보유 행의 절반을 지워 0 으로 두는데, 진짜 영상이 없는 행은 영벡터가 PCA 를 지나 0 이 아닌 값이
  됨. 모델이 배운 "영상 없음" 과 평가에서 만나는 값이 달라 결측 처리 실험 자체가 어긋나 있었음
- 수정: PCA 뒤에 영상 없는 행을 0 으로 맞춤

## 21. cosine 스케줄러의 하한이 한쪽 파라미터 그룹 기준으로만 걸림

- 증상: 백본(1e-4)과 헤드(1e-3)가 다른 학습률인데 `CosineAnnealingLR` 의 `eta_min` 을 헤드 기준 하나로 걸어, 헤드는
  20배, 백본은 2배만 감쇠함
- 수정: 배율로 거는 `LambdaLR` 로 바꿔 그룹마다 자기 초기 LR 에 곱해지게 함
- 결과: cosine 실행 21개를 다시 돌린 변화(−0.0060 \~ +0.0111)는 시드 변동폭보다 작았고 절제 순위도 그대로였음

## 22. 확인 실행이 절제 승자가 아닌 설정을 검증하고 있었음

이 항목은 라벨을 고치기 전(24번) 당시 이야기임. 그때 승자는 #5 freeze-0 이었고, 24번 뒤 다시 돌린 절제에서는 승자가
기준선(#1)임(report 확인 실행 절).

- 증상: 당시 확인 실행은 승자와 해상도, 배치, freeze 가 모두 다름
- 원인: 이를 막는 테스트(`test_confirmation_config_matches_ablation`)가 승자를 파일 이름(`02_aug-strong.json`)으로 찾아,
  그 기록이 없어지자 한 번도 돌지 않음
- 수정: 승자를 기록의 값으로 뽑음(`_ablation_winner()`, 시드 반복 회차 제외)
- 결과: 고친 테스트가 바로 불일치를 잡아 확인 실행을 다시 돌림

## 23. GBDT 의 시드가 어디에도 적혀 있지 않았음

- 증상: `build_tabular_model()` 이 `random_state` 를 넘기지 않음
- 원인: XGBoost 는 기본값이 0 으로 고정이지만 LightGBM 은 fit 시점의 전역 난수에서 뽑아, 앞 코드가 난수를 얼마나 썼는지에
  따라 값이 움직임
- 수정: 시드를 `GBDT_SEED`(0) 상수로 넘기고, 세 모델 모두 `random_state` 가 비어 있지 않은지 테스트함
  (`tests/test_metrics.py`)
- 결과: 당시 문서 수치는 바뀌지 않음. 지금 LightGBM AUROC 와 모델 폭은 라벨을 고친 뒤(24번) 다시 만든 0.7017, 0.0127 임

## 24. 재입원 라벨의 다음 입원을 걸러진 코호트 안에서만 찾고 있었음

- 증상: 30일 안에 다시 입원해도 그 입원이 하루를 못 채웠거나 원내 사망으로 끝났으면 음성이 됨
- 원인: 코호트 필터(성인, 재원 1일 이상, 원내 사망 제외)를 재입원 후보에도 적용함
- 수정: 다음 입원은 원본 admissions 전체에서 찾음(`src/cohort.py`, 과거 12개월 입원 수도 같음)
- 결과: Phase 1 부터 절제까지 전부 다시 만들었고, 주 분석 양성은 68,327 -> 79,509 건(16.46% -> 19.15%)이 됨
- 같은 점검에서 함께 고친 것
  - Phase 2 와 RAD-DINO 의 축소판 EHR 기준선(Phase 3 과 같은 피처로)
  - 절제 러너의 분할 시드(`--split-seed` 분리)
  - test 로 고르던 두 곳(교정 방식, RAD-DINO 뒷단. 이제 val 로)
  - 적합에 실패한 비교 모델 누락(`model_comparison_failed`)
  - 판정선 공유
- 결과: 바뀐 것은 ResNet50 영상 단독(영상을 봤다 -> 판단 보류)과 M2 뿐. 영상이 EHR 에 보태지 않는다는 결론과 누수
  A/B, 시간분할 판정은 그대로임
- 테스트: `tests/test_cohort_features.py`, `tests/test_runner_contracts.py`, `tests/test_output_claims.py`

## 25. Charlson 신장 질환의 ICD-9 코드가 넓게 잡혀 있었음

- 증상: mimic-code(커밋 303d26c)로 공식 `charlson` 테이블을 만들어 17항목을 입원별로 대조하자 신장 질환만 이 저장소 쪽
  양성이 많음
- 원인: ICD-9 정규식 `58[5-8]` 이 Quan 2005 에 없는 587, 588.1\~588.9 까지 잡아 160입원이 더 표시됨
- 수정: 585, 586, 588.0 으로 좁힘(`src/features.py`, `tests/test_cohort_features.py`). Phase 1 부터 다시 만듦(주 모델
  AUROC 0.7078 -> 0.7075)
- 결과
  - 고친 뒤 14항목이 같음. 나머지 셋은 중증이 있으면 경증을 0 으로 두는 표시 방식 차이임
  - 점수로는 415,231건 중 415,203건이 같음. 남은 28건은 Quan 2005 뒤에 생긴 ICD-10-CM 암 코드라 한계로 적음(MODEL_CARD
    한계 6)
- 비고: 과거 12개월 입원 수(365.28일)와 겹친 입원의 재입원 판정 정의도 문서에 적음
- 비고: 대조 코드와 공식 테이블은 저장소 코드와 따로 짜야 뜻이 있어 넣지 않음

## 26. DnCNN 한 시드가 아무것도 배우지 못함

- 증상: 첫 설정(Adam 1e-3 고정, 인내 5, 최대 30에폭)에서 train 손실이 크게 튀었고, 시드 2 의 최선 val 오차가 잡음 영상을
  그대로 둔 오차와 같음
- 수정: 공개 구현과 원 논문을 따라 1e-4 에서 시작해 멈추면 반으로 줄이고 인내 10, 최대 60에폭으로 세 시드를 다시 학습함
- 결과: 세 시드 모두 잡음 그대로보다 1.53\~1.56 dB 낫음
- 비고: 학습 기록에 잡음 그대로의 val 오차와 그 대비 개선(dB)을 함께 남김. 이 결정은 train, val 기록으로 내렸고 사전등록
  수정 이력에 적음
